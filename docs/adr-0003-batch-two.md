# Batch 2 architecture

Batch 2 extends the existing asset registry, immutable SHA-256 store and persistent per-item worker. `image.edit`, `video.process`, `audio.process` and `document.prepare` expose parameter schemas to the same operation API used by the UI. They do not mutate original objects. Saved results, parameters and source/tool provenance are stored in the additive `lab_asset_outputs` table. Output bundles contain checksums; individual artifacts can be adopted into Library and inspected, transformed or exported again.

Image previews execute the selected transform but serialize a bounded PNG for browser display. The output dimensions remain visible independently of preview dimensions. Transforms support crop, fit/pad, rotation, flip, color mode, format, brightness, contrast, sharpness, blur and contrast normalization. EXIF/GPS stripping is the default. Image transforms and inspection reject inputs/outputs above 64 megapixels.

Video and audio operations construct FFmpeg argument arrays without a shell. Media previews probe metadata and estimate output count without creating derivatives. Runs use bounded duration, a maximum of 500 extracted frames/segments, one FFmpeg encoding thread and a 30-minute subprocess timeout. Scene extraction uses FFmpeg's scene-change score; it is a visual heuristic rather than semantic scene understanding. Sample timestamps and actual output counts are recorded. Opus output uses 48 kHz, recorded in the result. Incompatible MP3 sample rates produce a validation error.

Knowledge preparation retains punctuation and source structure. Token, paragraph, heading and recursive strategies share a Unicode word-and-punctuation tokenizer with explicit provenance; counts are not model-specific BPE counts. The recursive strategy packs paragraphs and prefers sentence boundaries for long blocks. Cleanup uses bounded RE2 operations, Unicode normalization and whitespace cleanup. A transparent stopword language heuristic reports `und` when uncertain. Learned language detection, ASR and learned embeddings remain optional integrations. The current embeddings are an offline signed feature-hashing baseline. RAG export reads chunks, vectors and index metadata from a single database snapshot and streams original documents into the archive. No connector credential state is included.

Tesseract remains the preferred configured OCR provider. Windows can fall back to Windows.Media.Ocr and installed language capabilities without downloading a model. Word boxes and provider/OS revision are recorded; confidence is null because Windows does not supply it. FFmpeg and ffprobe can be configured through `.env` overrides with `scripts/configure-media-tools.py`, without changing system PATH.

Acquisition retains the existing downloader, provider registry, candidate state machine and target-yield controller. The new UI edits immutable plans, enables Test N/Start only after explicit consent, and provides paginated local candidate review. License/source-domain constraints execute before download. Disabling external access cancels acquisition at the next persisted candidate control check. Browser QA uses synthetic local candidates and does not contact discovery providers.
